# 未完成请求与承诺追踪 SOP

1. 优先查主人明确提出的请求、Agent 明确答应的事、需要后续确认的故障，以及带有时间条件的待办。先用消息 ID、会话和时间缩小范围，不把普通闲聊都列成任务。
2. 回看后续消息、工具结果、活动总结和现有事件，判断事项已完成、被新信息取代、仍待处理，还是无法确认。不要把“没有再提”当作完成。
3. 已完成或失效：更新/关闭原事件，不新建重复事件。仍待办：只在确有跨会话价值时更新已有事件，写清下一步、适用范围、期限或复核点。
4. 这项检查不授权主动给人发消息。只有原任务本来就要求联系、目标对象和上下文明确且此刻发送自然时，才考虑跨会话委托；否则只记真实待办。
5. 逐项确认事件更新结果；没有合适的未完成项就结束，不用“继续关注”制造无限期事项。
