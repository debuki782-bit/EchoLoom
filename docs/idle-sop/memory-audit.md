# 资料冲突与过期检查 SOP

1. 选一个对象或一个明确冲突，不做全库无目标清扫。优先从【客观增量盘点】提示的“碎片合并预警”对象（单人 `sender_memories >= 8` 或 `user_facts` 超限），以及近期纠错、互相矛盾、重复条目或原始来源已被明确否定的记录开始。
2. 对照原消息与来源 ID，分别核实 sender memory、用户事实、词典、消息备注和事件簿属于不同用途；不能因为内容相关就互相代替。
3. 执行 N 合 1 合并与纠错：重复或碎片化的同人同类记录，用 `query_wechat_archive_sql` 查出精确 `memory_id` 后先经 `sender_deletes` 删除冗余、再保留或写入精炼条目；错误 `user_facts` 用同一 `fact_key` 覆盖或标记清理；过期事件更新状态。存在歧义时保留并标明不确定，不盲目批量清空。
4. 检查写入工具结果及删除后的查询结果。没有具体冲突或碎片超标就不改，不把“资料看起来健康”写成大量维护成果。
