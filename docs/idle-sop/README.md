# 空闲活动 SOP 索引

每轮直接阅读本轮上下文下方已经注入的【最近空闲活动记录】（**不要**调用 `search_user_memory` 或 `search_message_notes` 去检索活动总结，它们不在事实表里）。

- **真·空窗才能快速退出**：请核对系统附带的【距上次空闲整理的客观增量盘点】。**只有当 `新增真人消息 == 0` 且无超 72 小时过期普通事件、无“碎片合并预警”、无明确未完待办或刚落地的项目改动时**，才允许跳过查询直接调用 `record_idle_activity` 结束。只要 `新增真人消息 > 0`，禁止零工具快退：必须先用 `query_wechat_messages` 实际审阅增量对话，再决定是沉淀新资料还是确认无稳定新条目后退出。
- **有实质增量时**：按下表选 **一项主任务**（只有直接紧密相关时才加一项配套小事），随后只读对应的一份 SOP；除非任务确实跨类别，不要把多份流程一起加载。若多个近期轮次反复暴露同一类可修正的行为/理解问题，确认充分证据后可查阅源码与提示词，通过 `update_own_prompt` 精准改进对应细则（注意核对预期 SHA-256，系统会自动保留可回滚快照；**修改时优先合并精简旧细则，避免提示词越攒越肥，个例尽量下沉到 `sender_memories` 或 `event_book`**）。

| 发现的线索 | 读取 |
|---|---|
| 明确请求、承诺、待回答事项可能没收尾 | `open-loops.md` |
| 某次回复认错人、漏接、误判或答错 | `conversation-review.md` |
| 语气显得陌生、警惕不足、模板化或过度热络 | `response-style.md` |
| 某个人出现了新的稳定身份、关系、称呼或偏好 | `sender-profile.md` |
| 新词反复出现，或已有词义可能混淆 | `dictionary.md` |
| 跨聊天事件可能完成、过期或有新进展 | `event-review.md` |
| 已有资料彼此冲突、重复、过时或类别放错 | `memory-audit.md` |
| 最近项目变更或具体技术问题值得核实 | `project-study.md` |
| 主人明确提过的兴趣有新线索可继续 | `interest-followup.md` |
| 线索涉及多种记忆类型，不确定该落在哪里 | `memory-curation.md` |

把最近活动和成功工具记录当作“做过什么”的证据。**尽量**换一个近期没做过的任务方向或目标对象；这不是硬限制：有新证据、明确未完成事项或需要纠错时可以继续，并说明本轮新增了什么。仅仅再读一次旧文档、再确认聊天安静、再复核一遍无变化的资料，不算新成果。

开始前说清本轮目标和完成标准；找到足够证据并完成或确认无需修改，就停止。写入只针对证据支持的资料，先核对现有记录和精确 ID，确认工具回执后再报告。活动总结简短写目标、依据、结果和真实未完事项；不要把推测写成事实，也不要为了显得有成果编造后续计划。
