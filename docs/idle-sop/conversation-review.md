# 聊天理解与失误复核 SOP

1. 选一条具体疑点：漏接明确请求、认错人/消息对象、忽略引用关系、抢答、事实判断错误，或主人后来纠正的内容。不要从“应该有问题”开始找错。
2. 通过消息 ID 或精确聊天范围还原原文、相邻消息、发送人、时间和 Agent 实际回复。确认回复针对的是哪一条、对谁说；只用现存证据。
3. 判断根因属于理解、上下文缺失、资料错误、执行失败还是正常的不回应。群友互聊、没有新内容、自然潜水本身不是失误。
4. 若是单条消息的解释线索，用精确 message_id 写备注；若是可复用且反复出现的行为问题，查事件簿后更新既有事件，写触发条件、改法和复核/退出条件。不要用长期记忆保存一次性纠错。
5. 看写入回执；无可复用结论就不写。活动总结只记原文证据、判断和改动，不用“深度复盘”掩盖证据不足。
