# ADR 0005：模型调用前的费用预留

状态：2026-10-29 采用为 **离线 M4 基础切片**；尚无真实模型调用。

schema v4 新增 `usage_reservations`，每条请求以 `request_id` 幂等记录账号、会话、功能、模型、UTC 月、最大预留微美元、实际微美元及 `reserved/settled/released` 状态。v1/v2/v3 升级前逐级备份。`UsageLedger.reserve` 在 SQLite `BEGIN IMMEDIATE` 事务中把同账号同月的未结预留和已结实际费用相加，再与调用方提供的预算上限比较；未预留成功的请求不得调用模型。应用内同进程并发测试验证不会超限。

成功响应按供应商返回的实际用量和已核价格结算。重复请求 ID 不重复占额；同 ID 参数变化报冲突。**仅确认请求从未进入可能计费的供应商链路时**才可释放预留；超时或结果不明时保留预留，等待人工或账单核对。实际费用超过预留时记录 `over_reservation` 并阻止后续超额预留，不能把应用预算描述为供应商硬封顶。

当前账本没有连接 Provider、模型价目配置或 Key，`maximum_microusd` 必须由后续经核价的请求估算器提供。真实接入前还需：账号 `models.list`、预算配置的持久化与鉴权、token 上限及含 thinking/工具成本的保守估算、供应商用量结算、异常恢复和跨进程压力测试。公开标价见[费用核验](../pricing-audit.md)。
